# Project Report 

### Introduction

Our Group decided to complete the IT Service Help Desk, which required us to create an application to raise, share, and solve the problems that occur during the creation of a project. The members within the organization can raise the ticket, re-open the ticket, and prioritize the ticket. The IT Help desk provides communication between project members and the IT team, as well as the IT team and the Report Manager. The IT service help desk provides a GUI Interface for all users (Report Manager, IT Team, Project Members, and Admin). The Project Member can either use an online help screen to view documents to help them solve the problem, or they can see a list of other solved tickets to find solutions. The application provides the option to raise a ticket if the project member is facing a new problem, and they can view the solution to a ticket when it’s solved. They also have the option to reopen a ticket if it’s closed without being solved. The IT Support team solves the ticket and can share the ticket with other team members if they can’t solve the issue. The report manager monitors the ticket status and can assign high-priority tickets to the IT team members. Administration can register and validate new users and generate reports. 

### Sprints 

In Sprint 0, we set up tools, picked team roles, and our project, and started working on our user stories. In the first sprint, we start on our login forms for the IT Help Desk. We created our login, admin, and registration forms, created our first ERD, and created the database for our project. In the second sprint, we connect our admin validation, login, and registration together to have a working login and registration form. We were also able to add different user forms to get ready for the work in our next sprint. In sprint 3, we added classes for our different users and a ticket class, as well as cleaned up our user and admin forms. We worked on adding basic functionality to our different user forms. In sprint 4, we focused on adding code to our ticket class and created a working project member form. In sprint 5, we finished our application by working on cleaning up our UI and finishing the report manager and the It support forms.

### Conclusions and Lessions Learned 

At the beginning of the semester, we all had some sort of clue–a basic understanding–of what Agile development entailed. However, this project certainly gives us first-hand experience with using this type of structure and technique. Working in these iterative, timed sprints gave us more time and leeway to finish small achievable goals, instead of getting overwhelmed with the project as a whole. We had been so used to you personally having to figure out how you were going to do things and not always given much of an actual schedule, this approach made the project seem more manageable. It showed that when it comes to software engineering, this iterative and agile development can be very powerful, with the importance of communication and collaboration.

Using an object-oriented approach was very crucial to our project. Using and designing with things such as a 3-tiered architecture made our system a lot clearer and manageable. Boundary/Entity/Controller classes helped reduce the complexity of individual aspects. From our experience, we realized how valuable an object-oriented approach was, and that behind a good design is intentional planning and frequent visiting, through things such as retrospective sprints.
Working as a team taught us a lot about flexibility, communication, and collaboration. One of the biggest challenges that we face is actually having time for all of us to actually work together. The times we were usually all available were during our scheduled class, sometimes even a little bit afterwards, and really late into the night, a few days during the semester. Other than that, we really improved our communication by using things like Messages and Trello. We were always stressing to each other to notify us of any delays or if we really needed someone to work on something. There was the flexibility of not having too much work on one singular person. With our successes and challenges, we gained valuable experience in teamwork that would most definitely be useful in the future.
